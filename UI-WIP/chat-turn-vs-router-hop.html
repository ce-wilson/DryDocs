Chat Turn vs Router Hop

Two architectures we keep comparing without naming the parts. This gives every block a handle — say TOOLDEF or R-DEC and we are pointing at the same object. The short version of the difference: an editor chat turn can think, choose from a menu of callable tools, and try again. The DryDocs router does none of those three.

Reference model

The editor-chat half is a generic model of how Agent / Ask / Plan modes generally work. It is not a claim about any specific product's internals, which are not public.

Read from the code

The router half is verified against this repo: agents/graph_qa/pipeline.py, envelope.py, providers.py, control.py.

The mode gate

Mode is a capability decision made before the first inference call. It sets which tools are offered, whether writes need approval, and whether the turn may iterate.

The DryDocs router pipeline

Same left-to-right job — question in, answer out — but the middle is a tiered classifier, not an agent loop. R-DEC is a single classification with no second chance: pick a registered spec, or fall through to generation.

Why the router misroutes, in these terms

Three blocks, absent together, explain what we saw in the jdoe4821 session:

  • No THINK. R-SYS asks for JSON with exactly two keys and no reason field, so no rationale is ever generated — there is nothing suppressed to recover.
  • No TOOLDEF. R-CAT is a list of ids to pick from, not tools the model may call with arguments and then reconsider. One pick, then the pipeline moves on.
  • No LOOP at Tier 0 or 1. A wrong route is terminal. Zero rows is a valid outcome, so nothing triggers a retry against a different spec — the run proceeds to A-SYS and explains the emptiness instead of questioning it.

An Agent-mode turn with the same wrong first guess recovers on the next pass, because OBS feeds back into INFER. The router has no such edge below Tier 2, which is why two of three runs reported "not ingested" for a document the corpus held all along.

Terms are handles for this conversation, not identifiers in the codebase — except the router-side ones drawn from real symbols (ROUTER_SYSTEM, ANSWER_SYSTEM, QuerySpec, fix_retries, StepRecord). Backlog item R18 is where the missing THINK equivalent is tracked.
