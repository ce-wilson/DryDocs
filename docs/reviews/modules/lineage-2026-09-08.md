## Lens 1 — system design

**This module's write boundary is the strongest read so far in the sweep**, and its one
consequential gap is not in what it writes — it is a declared state that nothing can
reach, and a counter that reports that state as a real zero.

### L1-1 — `dns-resolved` is a counted tier with no writer, so its metric is permanently 0

The server-resolution pass declares four outcomes for joining a Control-M node name to
an inventory `:Server` (`drydocs/loaders/server_resolution.py:10-18`): **T1 exact**,
**T2 normalized**, **T3 `dns-resolved`** and **UNMATCHED**. Its summary query counts all
of them, including:

```
sum(CASE WHEN 'dns-resolved' IN tiers THEN 1 ELSE 0 END)  AS matched_dns_resolved
```
(`server_resolution.py:54`)

T3 is documented as deliberately not built in that file — *"NOT BUILT here: the Z4
nslookup collector feeds the same edge + evidence shape from its canned-transcript
evidence file"* (`:16-17`). **The Z4 half exists and is closed.**
`drydocs_lineage/extractors/lb_resolution.py` is 396 lines, `Z4` is `status: done`
(2026-09-05), and it has a test (`tests/unit/test_lineage_lb_resolution.py`) and a shell
collector (`collect/lb_resolve.sh`).

**But nothing consumes it.** Verified three ways on this tree:

| check | result |
|---|---|
| production importers of `lb_resolution` | **0** (`source_scan.imported_modules` over `drydocs_lineage/`, `drydocs/`, `drydocs_core/`) |
| exported from `extractors/__init__.py` | **no** |
| in the `staging.py` extract chain | **no** |

Its sibling in the same "shell collects, Python parses" pattern is wired both ways:
`rua_inventory` is package-exported AND consumed by `archival.py`. So the inconsistency
is internal to the module's own convention, not a missing convention.

**Consequence.** `matched_dns_resolved` is structurally always zero, and it sits in a
summary beside `matched_exact` and `matched_normalized`, which are real. A reader sees
"0 resolved by DNS" and reads it as *no load-balancer aliases resolved* — the honest
statement is *this tier has no writer*. Meanwhile the jobs behind an LB alias stay
UNMATCHED and cannot be placed on a map, which is verbatim the gap
`lb_resolution.py`'s own docstring says it fills: the gate declared T3 *"for exactly
this and left unbuilt; this module is its evidence half."* The evidence half shipped;
the consuming half was never itemized. **Z3 and Z4 are both `done`, so no open item
covers it.**

**Cheapest correction:** one item to wire the Z4 evidence into the resolution pass —
either the pass reads the evidence file, or a `lineage-` verb emits the
`RESOLVES_TO_SERVER {match_tier:'dns-resolved'}` edges the shape already defines. Until
then the honest interim is one line: have the summary distinguish a tier with no writer
from a tier with no matches, so the zero stops asserting something false.

### L1-2 — what is genuinely strong, recorded so a later firing does not re-audit it

**The write boundary refuses rather than degrades**, which is the opposite of the
failure mode found in slots 2 and 9. `writer.py` states five contracts and enforces each
(`:1-35`): curated-only (only `confirmed` rels are written, and every one must already
exist in the graph), canonical identity (a `folder/job_name` fallback id is REFUSED,
`:171-177`), a `TrustBoundaryError` on trust violation, a `GateBoundVocabularyError` for
any label not `active`, and — the part worth copying elsewhere — **`plan_curated` is
PURE and computes exactly what a live load WOULD refuse, without a database** (`:336`),
so the plan print and the load cannot disagree.

**`archival.py` is the best epistemic writing in the sweep so far.** Because its output
drives deletion, it makes absence structurally unsayable: *"no axis proves absence"* —
referenced / present-on-server / registry-active are positive-only observations, every
"absent" statement reads as "not observed by feed X", a metadata-only run states its own
body-copy coverage in its own output, and the misdeployment finding is SUPPRESSED AND
COUNTED under unknown mount scope rather than emitted on a guess (`:1-26`). That is the
product thesis implemented at the one place where getting it wrong deletes live code.

**The module states its own past gap.** `staging.py:5-9` records that "nine extractors
and a curated writer existed for weeks with no verb that ran the chain and no verb that
loaded it" — LIN1 built the missing verbs. L1-1 is that same shape recurring one layer
out, which is worth noting: the module has already been bitten by *built but unreachable*
once and fixed it, and the next instance arrived through a different door.
