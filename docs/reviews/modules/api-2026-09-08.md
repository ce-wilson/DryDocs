## Lens 1 — system design

**This module has the best contract discipline in the sweep so far, and it has already
SOLVED the root cause the previous three slots each found.** Its one consequential gap is
that a correct behaviour it implements in exactly one place is not applied at the seam
where users meet it.

### L1-1 — a graph outage reaches the console as a 500, which the console is built not to recognize

`drydocs_api` catches a driver failure in **exactly one endpoint**, and does it well
(`app.py:480-490`): the graph-status route runs `RETURN 1 AS ok`, catches `Exception`,
and returns `GraphStatusOut(reachable=False, detail=type(exc).__name__)` — **the class,
never the message**, because a driver message quotes the URI it dialled and a page must
carry no host or port (ADR 0020). The comment even records that a wrong `NEO4J_URI`
first throws there rather than at server start, and that this is *"a reachable=false, not
a 500."*

**No other route does this.** Verified across the module: `ServiceUnavailable`, `503` and
`SessionExpired` appear **nowhere** in `drydocs_api/`, and there is no
`app.exception_handler` mapping driver classes to a status. So when Neo4j is down while
drydocs-api is up, `/specs/{spec_id}/run` — the workhorse behind every console grid —
propagates the driver exception and FastAPI answers **500**.

**Why that specific number matters.** The console decides "the service behind this path
is down" with `isUpstreamDown` (`web/src/lib/reachability.ts:45-47`), which is exactly
`502 || 503 || 504`. **500 is not in the set.** So during a graph outage every data page
renders a generic failure rather than "the graph is unreachable", while the one surface
that *could* say so is a separate probe the page may not have called. A support engineer
then debugs the console, or the API, for a database outage.

**Cheapest correction, and it is genuinely cheap:** one FastAPI exception handler mapping
the driver's error classes to **503**. No console change is needed — `isUpstreamDown`
already treats 503 correctly, and the reachability copy already exists. The one care
point is the same one `app.py:484` already names: pass the exception CLASS, never its
message, or the handler leaks the URI that ADR 0020 keeps out of the page.

### L1-2 — nothing in the module bounds how long a query may run

`timeout` appears nowhere in `drydocs_api/` outside `app.py`, and no spec, runner or
route sets one. The lens asks whether loading is distinguishable from hung; here it is
not, and there is no cancel and no retry. With 48 registered specs over a graph whose
`controlm_variables` extract documents a ~240k-row table, a heavy or pathological spec
holds the request until something upstream gives up — and what gives up first is the
proxy, which returns 504, which the console *does* read as "service down". So the
failure mode is: a slow query is reported to the user as a dead service.

Lower-ranked than L1-1 because it needs a decision (what ceiling is right, and per-spec
or global) rather than a handler, and because it degrades to a message that is at least
in the right family.

### L1-3 — what this module already gets right, recorded so no later firing re-audits it

**Completeness is DECLARED, and the consumer READS it.** This is the direct answer to the
root cause slots 9, 2 and 3 each found from a different side. `schemas.py:254` — *"API1
(d): completeness, declared. `truncated` says the spec's ceiling cut…"* — and the flag is
on the response, with `DEFAULT_DISPLAY_LIMIT = 500` as a named, tunable ceiling
(`query_specs.py:136`). The console consumes it rather than inferring it:
`web/src/explorer/SpecGrid.tsx:33` states *"COMPLETENESS IS READ, NEVER INFERRED"*, there
is a dedicated `TruncationBadge`, and `SpecGraphPane` passes `rowsTruncated`. **A working
remedy for the sweep's recurring finding exists in this repo, end to end, today.**

**The audit covers exactly the routes that change state — no more, no less.** 14 audited
routes. I checked the apparent gap and it is not one: `/mappings/changeset` is the only
mapping POST without an `audit_route`, and it is also the only one that performs no store
write — the three `mapping_store` mutations (`add_draft` ×2, `set_draft_status`) sit in
`/mappings/overrides/draft`, `/mappings/app-code/draft` and
`/mappings/drafts/{id}/promote`, all three audited. The audit is split by kind, too:
`api` never carries Cypher text or result values (an access record, not a data copy),
while `api-debug` does and is enabled settings-level so *"a per-request header would let
an untrusted caller turn on verbose capture of their own traffic"* (`audit.py:1-18`).

**Ephemeral specs are bounded on every axis that can leak.** Agent-key gated so a browser
bearer can never register Cypher, hash-addressed so the ref commits to what runs,
session-scoped with a 404 that does not leak existence, and both TTL- and
capacity-bounded with oldest-first eviction (`ephemeral_specs.py:1-30`). This is the
mechanism that lets `/raw-cypher` stay admin-gated rather than being loosened.
