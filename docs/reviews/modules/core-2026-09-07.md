## Venue defect found by this firing

Not a `drydocs_core` finding — a **sweep** finding, recorded here because it nearly
corrupted the measurements above and because the first firing is the only one that
can discover it.

The `review-sweep` worktree was created without an installed environment. The first
`poetry run pytest tests/unit` did not fail cleanly: it collected **this** worktree's
tests and resolved `drydocs_core` from **`ui-workstream/drydocs_core/`** — the other
worktree, on a different branch, at a different commit. The visible symptom was nine
collection errors naming modules that exist here and not there
(`drydocs_core.data_centers`, `drydocs_core.glossary`, `edition_registry`,
`ontology.domain_registry`), which reads as "core is missing modules" when it means
"you are reading the wrong tree."

Had those nine modules happened to exist in both trees, the run would have passed and
every number in this report would have described the wrong commit. `poetry install`
in the review worktree fixed it; `drydocs_core.__file__` was then re-checked to
confirm it resolves inside `review-sweep` before any measurement was trusted.

This is the J18 failure shape (a claim that does not name its venue) reached through
a path no naming convention prevents. It is a plan defect, not a code defect, and it
is listed as a grooming candidate.

## What holds

Core is in good condition, and on the two axes where the `web/` slot failed worst it
is the counter-example rather than a repeat.

- **No silent truncation anywhere.** No hidden `LIMIT`, no defaulted page size, no
  list slicing that caps a result. The single `LIMIT` in the package
  (`mapping_store.py:548`) is `LIMIT 1` on a single-row lookup. The top `web/`
  finding — an answer capped at 500 rows and presented as complete — has no
  equivalent here.
- **Failures are not swallowed.** Six `except Exception` handlers in 15,769 lines,
  two of which return a default. That is unusually disciplined for a package this
  size.
- **94% coverage over 5,484 statements**, with 3,410 tests passing and every skip
  carrying a stated reason (`google-adk lives in agents/.venv, not this
  interpreter`; gitignored production samples). Nothing skips silently.
- **`run_script` splits client-side and says why** (`neo4j_client.py:59`): a `;`
  inside a `//` comment can never shear a statement, which is the
  `apoc.cypher.runMany` landmine that Cypher 25 turns into a hard error. Each
  statement runs in its own auto-commit transaction so DDL and DML can share a file.
- **`connection_info()` returns the URI, user and database and deliberately not the
  password.**
- **`constraints_detail()` exists because names alone were not actionable** (G130) —
  the code records that a warning naming only a constraint sends the reader back to
  the database, and that deciding is the only action the check ever asks for.
- **The module boundary is declared in an importable object** (`component_map.py`)
  and enforced by a test, which is why this slot's scope could be resolved rather
  than retyped.

## Lens 1 — system design

### S1 — Core owns the driver seam, and it is the weakest of the three in the repo

There are three independent Neo4j driver constructions in first-party code:

| seam | site | consumers |
|---|---|---|
| `drydocs_core.Neo4jClient` | `drydocs_core/neo4j_client.py:33` | 13 component imports |
| the API's own driver | `drydocs_api/app.py:197` | the thin API (ADR 0005) |
| the agents' own driver | `agents/common/neo4j_tool.py:40` | graph_qa tooling |

Core's is the declared shared surface — the module map exists to say so, and
`__init__.py` exports `Neo4jClient` as one of its eight public names. It is also the
only one of the three with **no read routing, no read access mode, no notification
capture, and no close discipline beyond its context manager.**

The other two are not worse implementations that should be folded back into core.
They are *better* ones, each carrying a lesson core never received:

- The API pins `routing_=neo4j.RoutingControl.READ` (`app.py:219`) and
  `default_access_mode=neo4j.READ_ACCESS` on its export session (`app.py:229`).
- The API captures driver notifications alongside rows (`app.py:208`), and the code
  records why: discarding the summary is how **four unknown-label warnings presented
  as a clean empty answer on 2026-08-20.**
- The agents module carries an explicit `close_driver()` with a recorded reason — the
  driver deprecates relying on `Driver.__del__` and stops closing automatically in
  its 6.0 line.

**Consequence:** every fix learned at the edges stays at the edges. A loader or a
verify verb going through `drydocs_core.Neo4jClient` is still exposed to the exact
failure the API diagnosed, dated and fixed thirteen months of commits ago.

This is the `web/` review's root cause — a governing abstraction exists and the call
sites route around it — occurring in the module whose entire purpose is to *be* the
shared surface. It is the strongest argument in this report for why slot 10 exists.

### S2 — Every graph read in DryDocs runs inside a write transaction

`Neo4jClient.run` is the only query method, and it is unconditionally
`session.execute_write(...)` (`neo4j_client.py:57`).

Measured across `drydocs_core/`, `drydocs/`, `drydocs_api/`, `drydocs_lineage/` and
`drydocs_remediation/`: **`execute_write` appears exactly once — that line — and
`execute_read` appears nowhere.**

Four methods on the client are pure reads and all of them demand write access:
`server_version()` (`:89`), `apoc_available()` (`:98`), `constraint_names()`
(`:106`), and `constraints_detail()`.

**Consequence.** Core's client cannot be handed a read-only credential — a
least-privilege account fails on `RETURN apoc.version()`. In any clustered topology
every read is routed to the leader, so read replicas are unreachable through the
shared seam. And a caller cannot express intent: there is one method, it has one
access mode, and it is the dangerous one by default.

**Cheapest correction:** a second method, or an `access` argument, defaulting to
read. The API already demonstrates the shape.

### S3 — Core's client discards the driver's own diagnostics

`run()` returns `[dict(r) for r in tx.run(...)]` and drops the result summary.

The API does not, and its docstring (`app.py:208`) states the incident that changed
it: four unknown-label warnings presented as a clean empty answer on 2026-08-20, and
notifications are now always carried, never raised, with `[]` meaning a clean run
rather than a missing field.

**Consequence.** A component querying a mistyped label through core's client gets
`[]` and no signal. Empty-because-nothing-matched and empty-because-the-label-does-
not-exist are the same value. For a product whose thesis is provenance, a query
result that cannot say whether it was understood is the wrong default, and this is a
known failure with a date on it rather than a hypothetical.

### S4 — No timeouts, no retry policy, no cancellation in the entire package

Searched across all 74 files: the only `timeout` in `drydocs_core/` is an unrelated
`timeout=30` in `landing_zones.py:170`. There is no
`max_transaction_retry_time`, no per-transaction `timeout=`, no connection
acquisition timeout, and no cancellation path.

A hung or unreachable server hangs the caller indefinitely, and the loaders that run
the batch cadence are the callers. Loading and hung are indistinguishable — the same
finding the `web/` slot recorded as S5, at the other end of the same system.

### S5 — `apoc_available()` reports every failure as "APOC is missing"

```python
def apoc_available(self) -> bool:
    try:
        self.run("RETURN apoc.version() AS v")
        return True
    except Exception:
        return False
```

A dead database, a refused authentication, a wrong database name, a network
partition and a genuinely absent APOC plugin all return `False`.

**Consequence.** A caller branching on this reports "APOC not available" for a server
that is simply down, and an operator then goes looking for a plugin problem. This is
the same diagnosis-collapsing shape the console fixed with its reachability probe —
a dead server and a blocked origin being the same error — except here the collapse is
uncorrected and the message actively misdirects.

### S6 — Core has no declared public surface

`__init__.py:26` names seven modules plus `Neo4jClient`. The package has **34
top-level modules and subpackages**, and **22 of them are imported by components
while sitting outside `__all__`**:

| imports | module |
|---|---|
| 24 | `repo_paths` |
| 15 | `run_log` |
| 13 | `data_root`, `neo4j_client` |
| 8 | `mapping_store` |
| 6 | `data_zones` |
| 5 | `docs_verify`, `env_refs` |
| 4 | `schema`, `backlog_store` |
| 1-3 | `log_kinds`, `yaml_fragments`, `landing_zones`, `source_bindings`, `doc_anchors`, `env_doctor`, `data_centers`, `cypher_split`, `manual_mappings`, `docs`, `notifications`, `log_estate` |

**The most-imported module in core is not in its public surface.** `repo_paths` has 24
component call sites and no declaration that it was ever promised.

Nothing in `__all__` is unused, so this is not a stale export list — it is a list that
stopped growing while the package kept going. The consequence is that core has no
line between contract and internals: every module is equally importable and equally
undeclared, so a refactor cannot know what it is allowed to break. For the one module
that every component is permitted to import, that line is the whole point.

(Five modules are imported by no component: `component_map`, `edition_registry`,
`entity_extract`, `glossary`, `ui_concepts`. All five have real consumers — the four
component `__init__` shims and `scripts/render_module_map.py`, the groom-backlog
validator and `tests/`, and the `agents/graph_qa` tooling. None is dead; they are
consumed by readers outside the component set, which is itself an argument that the
public surface needs stating.)

### S7 — The context-manager contract is enforced by `assert`

`neo4j_client.py:54` and `:72` both guard with
`assert self._driver is not None, "Use Neo4jClient as a context manager"`.

Assertions are removed under `python -O`. Core is a library that other packages
import, so the interpreter flags are not its own to choose; under `-O` a client used
outside its context manager reaches `self._driver.session(...)` and raises
`AttributeError: 'NoneType' object has no attribute 'session'` instead of the
sentence that tells the caller what they did wrong. The cost of correcting this is a
`raise RuntimeError` in place of each `assert`.

### S8 — A live setting is justified by a retired platform

`neo4j_client.py:28` explains `liveness_check_timeout=0` as "preventing
SessionExpired on **Aura**." Aura was ruled out on 2026-07-06 in favour of the local
Docker Enterprise container, and the only surviving Aura references in the tree are
in ADR 0015 as a per-team future option.

The setting is probably still right — pooled-connection staleness is not
Aura-specific — but its recorded reason names a platform this repo no longer targets.
In a codebase whose comments carry its rulings, a justification that has expired is
worth one line of correction, because the next reader deciding whether to remove the
setting will weigh it against a platform that is not in play.
