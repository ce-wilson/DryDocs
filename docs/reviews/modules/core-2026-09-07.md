## Venue defect found by this firing

Not a `drydocs_core` finding — a **sweep** finding, recorded here because it nearly
corrupted the measurements above and because the first firing is the only one that
can discover it.

The `review-sweep` worktree was created without an installed environment. The first
`poetry run pytest tests/unit` did not fail cleanly: it collected **this** worktree's
tests and resolved `drydocs_core` from **`ui-workstream/drydocs_core/`** — the other
worktree, on a different branch, at a different commit. The visible symptom was nine
collection errors naming modules that exist here and not there
(`drydocs_core.data_centers`, `drydocs_core.glossary`, `edition_registry`,
`ontology.domain_registry`), which reads as "core is missing modules" when it means
"you are reading the wrong tree."

Had those nine modules happened to exist in both trees, the run would have passed and
every number in this report would have described the wrong commit. `poetry install`
in the review worktree fixed it; `drydocs_core.__file__` was then re-checked to
confirm it resolves inside `review-sweep` before any measurement was trusted.

This is the J18 failure shape (a claim that does not name its venue) reached through
a path no naming convention prevents. It is a plan defect, not a code defect, and it
is listed as a grooming candidate.

## What holds

Core is in good condition, and on the two axes where the `web/` slot failed worst it
is the counter-example rather than a repeat.

- **No silent truncation anywhere.** No hidden `LIMIT`, no defaulted page size, no
  list slicing that caps a result. The single `LIMIT` in the package
  (`mapping_store.py:548`) is `LIMIT 1` on a single-row lookup. The top `web/`
  finding — an answer capped at 500 rows and presented as complete — has no
  equivalent here.
- **Failures are not swallowed.** Six `except Exception` handlers in 15,769 lines,
  two of which return a default. That is unusually disciplined for a package this
  size.
- **94% coverage over 5,484 statements**, with 3,410 tests passing and every skip
  carrying a stated reason (`google-adk lives in agents/.venv, not this
  interpreter`; gitignored production samples). Nothing skips silently.
- **`run_script` splits client-side and says why** (`neo4j_client.py:59`): a `;`
  inside a `//` comment can never shear a statement, which is the
  `apoc.cypher.runMany` landmine that Cypher 25 turns into a hard error. Each
  statement runs in its own auto-commit transaction so DDL and DML can share a file.
- **`connection_info()` returns the URI, user and database and deliberately not the
  password.**
- **`constraints_detail()` exists because names alone were not actionable** (G130) —
  the code records that a warning naming only a constraint sends the reader back to
  the database, and that deciding is the only action the check ever asks for.
- **The module boundary is declared in an importable object** (`component_map.py`)
  and enforced by a test, which is why this slot's scope could be resolved rather
  than retyped.

## Lens 1 — system design

### S1 — Core owns the driver seam, and it is the weakest of the three in the repo

There are three independent Neo4j driver constructions in first-party code:

| seam | site | consumers |
|---|---|---|
| `drydocs_core.Neo4jClient` | `drydocs_core/neo4j_client.py:33` | 13 component imports |
| the API's own driver | `drydocs_api/app.py:197` | the thin API (ADR 0005) |
| the agents' own driver | `agents/common/neo4j_tool.py:40` | graph_qa tooling |

Core's is the declared shared surface — the module map exists to say so, and
`__init__.py` exports `Neo4jClient` as one of its eight public names. It is also the
only one of the three with **no read routing, no read access mode, no notification
capture, and no close discipline beyond its context manager.**

The other two are not worse implementations that should be folded back into core.
They are *better* ones, each carrying a lesson core never received:

- The API pins `routing_=neo4j.RoutingControl.READ` (`app.py:219`) and
  `default_access_mode=neo4j.READ_ACCESS` on its export session (`app.py:229`).
- The API captures driver notifications alongside rows (`app.py:208`), and the code
  records why: discarding the summary is how **four unknown-label warnings presented
  as a clean empty answer on 2026-08-20.**
- The agents module carries an explicit `close_driver()` with a recorded reason — the
  driver deprecates relying on `Driver.__del__` and stops closing automatically in
  its 6.0 line.

**Consequence:** every fix learned at the edges stays at the edges. A loader or a
verify verb going through `drydocs_core.Neo4jClient` is still exposed to the exact
failure the API diagnosed, dated and fixed thirteen months of commits ago.

This is the `web/` review's root cause — a governing abstraction exists and the call
sites route around it — occurring in the module whose entire purpose is to *be* the
shared surface. It is the strongest argument in this report for why slot 10 exists.

### S2 — Every graph read in DryDocs runs inside a write transaction

`Neo4jClient.run` is the only query method, and it is unconditionally
`session.execute_write(...)` (`neo4j_client.py:57`).

Measured across `drydocs_core/`, `drydocs/`, `drydocs_api/`, `drydocs_lineage/` and
`drydocs_remediation/`: **`execute_write` appears exactly once — that line — and
`execute_read` appears nowhere.**

Four methods on the client are pure reads and all of them demand write access:
`server_version()` (`:89`), `apoc_available()` (`:98`), `constraint_names()`
(`:106`), and `constraints_detail()`.

**Consequence.** Core's client cannot be handed a read-only credential — a
least-privilege account fails on `RETURN apoc.version()`. In any clustered topology
every read is routed to the leader, so read replicas are unreachable through the
shared seam. And a caller cannot express intent: there is one method, it has one
access mode, and it is the dangerous one by default.

**Cheapest correction:** a second method, or an `access` argument, defaulting to
read. The API already demonstrates the shape.

### S3 — Core's client discards the driver's own diagnostics

`run()` returns `[dict(r) for r in tx.run(...)]` and drops the result summary.

The API does not, and its docstring (`app.py:208`) states the incident that changed
it: four unknown-label warnings presented as a clean empty answer on 2026-08-20, and
notifications are now always carried, never raised, with `[]` meaning a clean run
rather than a missing field.

**Consequence.** A component querying a mistyped label through core's client gets
`[]` and no signal. Empty-because-nothing-matched and empty-because-the-label-does-
not-exist are the same value. For a product whose thesis is provenance, a query
result that cannot say whether it was understood is the wrong default, and this is a
known failure with a date on it rather than a hypothetical.

### S4 — No timeouts, no retry policy, no cancellation in the entire package

Searched across all 74 files: the only `timeout` in `drydocs_core/` is an unrelated
`timeout=30` in `landing_zones.py:170`. There is no
`max_transaction_retry_time`, no per-transaction `timeout=`, no connection
acquisition timeout, and no cancellation path.

A hung or unreachable server hangs the caller indefinitely, and the loaders that run
the batch cadence are the callers. Loading and hung are indistinguishable — the same
finding the `web/` slot recorded as S5, at the other end of the same system.

### S5 — `apoc_available()` reports every failure as "APOC is missing"

```python
def apoc_available(self) -> bool:
    try:
        self.run("RETURN apoc.version() AS v")
        return True
    except Exception:
        return False
```

A dead database, a refused authentication, a wrong database name, a network
partition and a genuinely absent APOC plugin all return `False`.

**Consequence.** A caller branching on this reports "APOC not available" for a server
that is simply down, and an operator then goes looking for a plugin problem. This is
the same diagnosis-collapsing shape the console fixed with its reachability probe —
a dead server and a blocked origin being the same error — except here the collapse is
uncorrected and the message actively misdirects.

### S6 — Core has no declared public surface

`__init__.py:26` names seven modules plus `Neo4jClient`. The package has **34
top-level modules and subpackages**, and **22 of them are imported by components
while sitting outside `__all__`**:

| imports | module |
|---|---|
| 24 | `repo_paths` |
| 15 | `run_log` |
| 13 | `data_root`, `neo4j_client` |
| 8 | `mapping_store` |
| 6 | `data_zones` |
| 5 | `docs_verify`, `env_refs` |
| 4 | `schema`, `backlog_store` |
| 1-3 | `log_kinds`, `yaml_fragments`, `landing_zones`, `source_bindings`, `doc_anchors`, `env_doctor`, `data_centers`, `cypher_split`, `manual_mappings`, `docs`, `notifications`, `log_estate` |

**The most-imported module in core is not in its public surface.** `repo_paths` has 24
component call sites and no declaration that it was ever promised.

Nothing in `__all__` is unused, so this is not a stale export list — it is a list that
stopped growing while the package kept going. The consequence is that core has no
line between contract and internals: every module is equally importable and equally
undeclared, so a refactor cannot know what it is allowed to break. For the one module
that every component is permitted to import, that line is the whole point.

(Five modules are imported by no component: `component_map`, `edition_registry`,
`entity_extract`, `glossary`, `ui_concepts`. All five have real consumers — the four
component `__init__` shims and `scripts/render_module_map.py`, the groom-backlog
validator and `tests/`, and the `agents/graph_qa` tooling. None is dead; they are
consumed by readers outside the component set, which is itself an argument that the
public surface needs stating.)

### S7 — The context-manager contract is enforced by `assert`

`neo4j_client.py:54` and `:72` both guard with
`assert self._driver is not None, "Use Neo4jClient as a context manager"`.

Assertions are removed under `python -O`. Core is a library that other packages
import, so the interpreter flags are not its own to choose; under `-O` a client used
outside its context manager reaches `self._driver.session(...)` and raises
`AttributeError: 'NoneType' object has no attribute 'session'` instead of the
sentence that tells the caller what they did wrong. The cost of correcting this is a
`raise RuntimeError` in place of each `assert`.

### S8 — A live setting is justified by a retired platform

`neo4j_client.py:28` explains `liveness_check_timeout=0` as "preventing
SessionExpired on **Aura**." Aura was ruled out on 2026-07-06 in favour of the local
Docker Enterprise container, and the only surviving Aura references in the tree are
in ADR 0015 as a per-team future option.

The setting is probably still right — pooled-connection staleness is not
Aura-specific — but its recorded reason names a platform this repo no longer targets.
In a codebase whose comments carry its rulings, a justification that has expired is
worth one line of correction, because the next reader deciding whether to remove the
setting will weigh it against a platform that is not in play.

## Lens 2 — technical debt

Core carries very little conventional debt. The escape-hatch census is almost empty:
**3 `type: ignore`, 0 `cast()`, 0 `noqa`, 1 `TODO`** — and that TODO
(`component_map.py:211`) is a note recording that an ADR 0002-a TODO was *resolved*.
Ruff passes on both `check` and `format`. There is no dead dependency question here
because core declares none of its own.

The abstraction-bypass shape that dominated the `web/` slot is largely absent too.
`repo_paths.repo_root()` is the path-resolution helper; across 74 files there are
three raw `Path(__file__).resolve().parents[...]` walks, and **two of them pass their
result through `repo_root()`** (`orchestration/crosswalk.py:38`,
`orchestration/shell.py:48`). One bypasses it outright
(`ontology/schema_graph.py:75`). One bypass, not twelve.

So the findings below are narrower and mostly about what the package cannot see about
itself.

### T1 — The module that must never fail cannot report that it failed

`run_log.py` holds **four of core's six** `except Exception` handlers. Each is
reasoned in place, and each reason is good:

| line | comment |
|---|---|
| 81 | a broken declaration must not take the loaders with it |
| 121 | an unreadable declaration falls back to the old shape |
| 146 | audit trail, never the failure |
| 191 | some CI environments have no user |

None of them logs anything. The module imports and uses a logger elsewhere — eight
warn-level mentions — but not on any of these four paths.

**And every one of the four is untested.** Coverage of `run_log.py` is 85%, 22 of 151
statements uncovered, and the missing ranges are:

```
81-86, 121-123, 146-147, 191-192, 212, 247-248, 258-259, 304-307
```

The first four ranges are exactly the four handlers and their fallback bodies. The
module designed never to fail has its never-fail paths as its only substantially
untested code, and nothing would report a degradation if one occurred.

The specific consequence: `_log_root()` normally delegates to
`log_kinds.resolve_root()`, which validates the declaration and emits the
"`SPIDERP_LOGDIR` is deprecated and is honored for one more cycle" warning. When that
call raises, line 81 catches it and falls back to reading the environment variables
directly — so a broken declaration silently costs both the validation and the
deprecation warning, and the run continues writing logs somewhere with no note that
the declared resolution was bypassed.

**Cheapest correction:** one `LOGGER.warning` per handler, saying which path
degraded. The infrastructure is already imported. Testing the four branches follows
naturally once they emit something observable.

### T2 — The deprecation vocabulary is domain modeling, not decay, and a raw grep says otherwise by a factor of seven

Recorded because it is a measurement about *reviewing* this repo, and because it is
the J66 rule paying for itself inside the review that cites it.

A raw substring search for `deprecated|legacy|superseded|temporary` over
`drydocs_core/` returns **83 matches** — which, reported as-is, would read as a
package riddled with decay markers. Re-run through `tests/source_scan.code_only`,
which strips comments and string literals, it returns **12 occurrences across 9
files**. Reading those twelve, almost all are *field names modeling the domain*:

- `edition_registry.legacy_band` — the allocator's producer/company id bands
- `ontology/domain_registry.superseded_by` — a domain's successor pointer, with
  validation that a deprecated domain names one and an active domain does not
- `schema/supplements.legacy_verb` — a supplement's previous verb name
- `adapters/controlm/api.py` — Control-M's own "XML deprecated from 9.0.21.100 but
  fully supported until 9.0.22" version window, which is vendor fact, not our debt

Two are genuine compatibility shims: the `SPIDERP_LOGDIR` / `SPIDERP_CALLER`
environment aliases (`run_log.py:51,53`). Their retirement is tracked — G104, G105,
G125 and V2 all reference them — so they are carried debt with a home, not
unnoticed debt.

The finding is therefore not "core has 83 debt markers." It is that **the obvious
measurement is wrong here by roughly 7:1**, and any future sweep or tool that counts
markers by substring over this repo will manufacture findings. The guard rule exists
for the code; it applies to the reviewer identically.

### T3 — Three type escapes, one idiom, trivially removable

```
adapters/csv_adapter.py:39     self._fh = None      # type: ignore[assignment]
adapters/oracle_adapter.py:67  self._conn = None    # type: ignore[assignment]
adapters/oracle_adapter.py:68  self._cursor = None  # type: ignore[assignment]
```

All three are the same shape: an adapter declares a handle as non-optional, then
assigns `None` in `__init__` before `connect()` runs. The correction is to type the
attribute as optional and let the connect path narrow it — which also documents the
real lifecycle, that these adapters have a valid unconnected state.

This is the same seam the `web/` slot found its 21 double casts at: the boundary
between a resource's declared type and its actual lifetime. Core has three; the
console had twenty-one.

### T4 — A core module's tests cannot be found by its name

66 modules; **26 have a same-named `test_<module>.py`, 40 do not**, including the
largest: `models/seal.py` (542 lines), `env_refs.py` (540), `models/controlm.py`
(538), `orchestration/shell.py` (535), `adapters/controlm/api.py` (478).

**This is not a coverage gap and must not be read as one** — package coverage is 94%
and none of those five files appears in the sub-90% table, so they are well
exercised. The tests are organised by concern (`test_loader_run_log.py`,
`test_sql_run_log.py` both cover `run_log.py`) rather than by module.

The cost is navigation, and it is real but small: a reader changing
`orchestration/shell.py` has no name-based way to find what guards it, and must
either grep or run coverage. Worth a line in `MODULE_MAP.md` naming the convention
that is actually in use, rather than renaming forty test files.

### T5 — The undeclared public surface is a debt with no blast radius

The system-design statement of this is S6. In debt terms: 22 core modules are
imported by components while sitting outside `__all__`, so **no refactor of a core
module can determine what it is allowed to break.** `repo_paths` has 24 call sites
and no declaration that it was ever promised; changing its signature is either a
routine internal edit or a breaking change to a third of the repo, and nothing in the
package says which.

This is the cheapest of the structural findings to correct and the one that compounds
fastest, because every module added to core without a decision about its visibility
widens the ambiguity.

## Cross-links

**To the `web/` slot (`web-2026-09-05.md`), which is the only prior report:**

- **S1 is that review's root cause, one layer down.** The web report closed by naming
  a shape that recurred eight times: *a governing abstraction exists, is correct, and
  the call sites route around it.* S1 is the same shape in the module that exists to
  *be* the shared abstraction — and with the polarity reversed, because here the call
  sites did not route around a correct helper, they outgrew a stale one. That
  distinction matters for the fix: the console's answer was to make the helper the
  only path; core's answer has to be to raise the helper to the level of its callers
  first.
- **S4 is the console's S5 at the other end of the same system.** The console has no

  hung page is waiting on two layers that both chose to wait forever.
- **S5 is the console's O85 probe, uncorrected.** The console distinguishes a dead
  server from a blocked origin because collapsing them misdirected people. Core
  collapses "server down" into "APOC missing," which misdirects harder — it names a
  specific wrong cause rather than being merely vague.
- **The truncation finding does not transfer, and that is worth recording.** The
  console's top finding was a 500-row cap presented as a complete answer. Core has no
  silent cap anywhere. The provenance failure was introduced at the presentation

- **T3 is the console's T5 at one-seventh scale**, at the same seam: three type
  escapes against twenty-one double casts, both where a declared type meets an actual
  lifetime.
- **Coverage inverts completely**: 94% here against 7.51% there. Same repo, same
  guards available, opposite outcomes — which suggests the console's coverage gap is

## Candidates for grooming

Named only. No ids minted, no item files written, no epic assigned — `groom-backlog`
owns that.

1. **Raise `Neo4jClient` to the level of its two younger siblings** (S1, S2, S3): a
   read access mode, notification capture, and a decision recorded about whether the
   API and agents should then adopt it or stay separate. Large enough to want an ADR
   rather than an item — see below.
2. **Timeout and retry policy for core's driver** (S4). Small, self-contained, and
   the kind of thing that is cheap now and expensive after the first production hang.
3. **`apoc_available()` should distinguish "cannot reach" from "not installed"**
   (S5). Very small.
4. **Declare core's public surface** (S6, T5). The decision is bigger than the edit:
   either `__all__` grows to describe reality, or a convention marks internals, or
   the boundary test gains a second axis. Worth one ruling, not four opinions.
5. **`run_log`'s degradation paths should say they degraded** (T1), and the four
   branches should get tests once they emit something observable.
6. **Three `type: ignore` removals in the adapters** (T3). Trivial; good first item.
7. **Correct the Aura justification** (S8). One comment line.
8. **SWEEP DEFECT, not a core item — the review worktree needs a declared
   environment step.** The first firing found that `review-sweep` had no installed
   environment and that the failure was not clean: pytest resolved `drydocs_core`
   from the *other* worktree while running this tree's tests, and would have passed
   silently if the module sets had happened to match. The plan's section 4 step 0
   should require `poetry install` and an explicit
   `drydocs_core.__file__` venue assertion before any measurement is trusted. This is
   the highest-value thing this firing learned and it is about the sweep, not
   about core.

**ADR candidates** (nominated, not written):

- *The graph driver seam*: one client policy for reads, writes, notifications,
  timeouts and close discipline, and whether the API and agent tiers adopt it or are
  explicitly exempted. S1 through S4 are all downstream of this one decision.
- *What of core is public*: whether `drydocs_core` declares a contract surface
  distinct from its internals, and if so how the boundary test enforces it.
