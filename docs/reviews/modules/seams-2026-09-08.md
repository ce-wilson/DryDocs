## Lens 1 — system design

**The module boundary is enforced against STATIC imports only, and there are already two
undeclared crossings expressed dynamically.** This is the finding no per-module slot could
reach: slot 7 reviewed the port component thoroughly, gave it perfect hatch scores, and
could not have seen this — because the crossing is invisible to the instrument, so the
module reads as clean from inside.

### L1-1 — `drydocs-port` imports `drydocs-remediation`, and the guard cannot see it

`drydocs/port/reconcile_before.py:211`:

```python
detect = importlib.import_module("drydocs_remediation.detect")
put("detect-rule-ids.txt", "
".join(detect.CONFORMANCE_RULE_IDS))
```

Classified through `component_map`, both ends and the exemptions:

| | |
|---|---|
| source | `drydocs.port.reconcile_before` → group `port` → **`drydocs-port`** |
| target | `drydocs_remediation.detect` → group `remediation` → **`drydocs-remediation`** |
| entrypoint exemption | **no** (`ENTRYPOINT_MODULES` does not cover it) |
| `DECLARED_COMPONENT_IMPORTS` | **absent** — the only entry is `agents.common.specs_catalog` |

So it is a component-to-component import, undeclared and unexempted, and
`test_components_do_not_import_each_other` passes because the guard walks `ast.Import` and
`ast.ImportFrom` nodes and this is a **function call with a string literal**.

**A second crossing, of a different kind, on line 216:** `importlib.import_module(
"tests.unit.test_runbook_currency")` — production code reaching into the **test tree** for
three exemption tables. Also invisible, and not a boundary the guard models at all.

**The code itself is well-reasoned, and saying so is part of the finding.** The comment
above both calls reads *"J51 optional list-shaped snapshots — the module may not exist on
this side"*: `reconcile_before` runs on BOTH sides of the port, and `drydocs_remediation`
is not guaranteed to exist on the company tree, so a static import would fail at import
time there. Both calls sit in `try/except ImportError` and both **record the omission**
(`report.skipped.append(...)`) rather than silently dropping it — which is, once again,
the completeness discipline this sweep has found six times.

**So the defect is not the import. It is that the invariant is unenforceable as written.**
Three consequences, in order:

1. **The declared-exception list is incomplete, and it is the thing people read.**
   `DECLARED_COMPONENT_IMPORTS` says the architecture has exactly one sanctioned
   cross-component edge. It has at least two. A reader auditing coupling — or a Team
   Edition copier deciding what a component drags with it — gets a wrong answer from the
   authoritative object.
2. **The rule is bypassable without intent.** Nothing announces that `importlib` escapes
   the boundary check. A developer solving the same cross-tree-optionality problem
   reaches for the same construct and creates an undetected dependency, correctly, in
   good faith.
3. **`test_declared_component_imports_are_load_bearing` cannot protect what it cannot
   see.** That test is the guard's best idea — it fails a declared exception that has gone
   stale, on the reasoning that *"a stale exception is worse than no exception: it silently
   widens the boundary for a module that no longer needs it, and nothing fails to say so."*
   An UNDECLARED exception is that same failure one step earlier, and outside its reach.

**Cheapest correction, and it is two small pieces:**
- **Detect the construct.** Extend the guard to treat `importlib.import_module("<literal>")`
  and `__import__("<literal>")` as imports when the argument is a string constant. This is
  a dozen lines against the AST it already walks, it is exact for the literal case, and
  the literal case is all three sites in the tree.
- **Declare the two crossings.** `drydocs.port.reconcile_before → drydocs_remediation` is
  legitimate and should be in `DECLARED_COMPONENT_IMPORTS` so the list is true and the
  load-bearing test starts protecting it. The `tests.unit.*` reach is a separate question
  and probably wants a different answer (move the three tables to a non-test home) rather
  than a declaration.

A dynamic import built from a variable stays invisible, and should be recorded as the
residual rather than solved: the guard would be claiming more than it can deliver.

### L1-2 — the invariant itself holds, which is the other half of the result

Re-derived independently (see Measurements): 276 files, 15 cross-group edges, **zero
static violations** once the single declared exception is applied. Core imports no
component; components import only core. That is worth stating plainly because eight slots
of findings can leave an impression the architecture is fraying, and it is not — the
boundary is real, enforced, and observed. What this slot found is one hole in the
*instrument*, not a hole in the design.

## Lens 2 — technical debt

Two results, both of which only this slot could produce: a **twin-hunt measured across the
whole test tree**, and the **sizing question** slots 6 and 7 deferred here.

### L2-1 — the guard-reads-prose class is wider than its two known instances, and nobody has swept it

Slot 2 found LOAD5 (`test_recursive_sql_cyclic_type_disabled` asserting a comment phrase;
fixed on `main` at `e15d319a`). Slot 5 found the same class again in
`test_remediation_changes.py:323` (still open). Two independent instances in two slots is
what made this a class rather than a bug — and neither slot could see how wide it is.

Measured across `tests/`:

| | |
|---|---|
| tests importing the correct instrument (`tests/source_scan.py`) | **14** |
| tests that read **Python source** raw AND assert a substring on it | **18** |
| of those, importing `source_scan` anywhere | 3 |
| of those, **raw only** | **15** |

**What this does and does not establish.** It does NOT establish 15 defects, and this
report will not claim that: J66 names an explicit exception — *"a guard whose subject IS
the prose"*, asserting an error message or an operator-facing string, reads raw source on
purpose. Some of the 15 are certainly that. What it establishes is that **the class has
18 candidate sites, exactly 2 have ever been examined, both examined turned out to be
real, and no sweep exists.** A 2-for-2 sample over 18 is not proof, but it is the reason
to look at the other 16 rather than assume.

**Why it belongs to this slot.** `tests/source_scan.py` offers `code_only`,
`without_prose`, `imported_modules`, `called_names`, `call_sites`, `comment_lines` and
`absent` — a complete instrument, used by 14 tests and bypassed at roughly the same
number. **The instrument is not missing; it is optional.** That is the same shape as
Lens 1's finding one layer up (a boundary rule that only covers the construct people
happen to use) and the same shape as the completeness pattern across all eight module
slots: **in this repo the correct answer reliably exists and reliably fails to propagate.**

**Cheapest correction:** not "fix 15 tests". Triage the 18 against J66's stated exception,
convert the ones whose subject is code, and — the part that stops it recurring — decide
whether `source_scan` is the mandatory route for a source-reading guard and give
`test_source_scan.py` a check that a new raw-read guard has to justify itself.

## Cross-links

**The conclusion of the cycle, which is the thing slot 10 exists to say.**

Across nine module reports the sweep found one defect shape seven times — a result that
cannot distinguish *checked and clean* from *not checked*:

| slot | the instance |
|---|---|
| 9 `web` | a console that truncated silently |
| 2 `load` | a `:JobRun` that records no scope, so a sample looks like a full load |
| 3 `lineage` | a counted `dns-resolved` tier with no writer |
| 5 `remediation` | a findings list with no rule denominator (17 of 45) |
| 6 `review-agents` | four of six acceptance suites that cannot fail on an empty graph |
| 7 `port-docgen-docmeta` | a preflight that certifies a base it could not read |
| 10 `seams` | a boundary rule that only sees the construct people happen to use |

And it found the **correct answer implemented independently six times**: `equivalence.py`'s
three-valued **not proven** (*"no evidence is never evidence"*), `archival.py`'s
coverage-stated-on-itself, `drydocs_api`'s declared `truncated` **read** by the console
rather than inferred, `port_preflight`'s *"SKIPPED — not a certification"*, `plan_board`'s
**"no items"** rather than `0 / 0`, and `deepdoc`'s scaffold-status paragraph naming which
of its own bodies raise.

**Six correct implementations. Zero written conventions. Seven recurrences.**

Slot 8 framed it and this slot's own findings confirm it from a different layer: **this is
not a repo that gets completeness wrong. It is a repo where the right answer does not
propagate.** L1-1 and L2-1 are the same disease in the tooling — a boundary rule that
covers `import` but not `import_module`, and a source-reading instrument that 14 tests use
and 15 bypass. In every case the knowledge exists, is written down somewhere specific, and
never becomes the thing the next author inherits.

That distinction decides the fix. A repo that gets something wrong needs education. A repo
where a solved problem does not travel needs **a written convention and an instrument that
makes the wrong version fail** — because six correct implementations already prove nobody
needs convincing.

**To the second pass.** Slot 9 (`web`) is the oldest report (2026-09-05) and will be first
when the rotation comes round. It is also the slot whose top finding — silent truncation —
was later solved by `drydocs_api` declaring `truncated`. **The second pass on `web` should
begin by checking whether that fix reached every consumer**, because that is precisely the
propagation question this cycle ends on, and `web` is where it can be answered with a
number.
