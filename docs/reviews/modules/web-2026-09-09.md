## Lens 1 — system design

**The prior report's ranked #1 is still open, and the second pass can now say something the
first could not: it is two different failures wearing one symptom.** Dating the contract
against the surfaces separates them, and they need different fixes.

### L1-1 — the truncation contract reached three of eight consumers, and the gap splits in two

`truncated` entered `drydocs_api/schemas.py` on **2026-09-05** (`95c89328`, extended
`3d159a59` on 09-08) — the same day the first web review was written. Dating each surface
that drops it against that:

| surface dropping the flag | added | relative to the contract |
|---|---|---|
| `routes/IntakeRoute.tsx` | 2026-08-10 | **predates** it by 26 days |
| `components/map/LocationMap.tsx` | 2026-08-22 | **predates** it by 14 days |
| `ask/FileReport.tsx` | 2026-08-31 | **predates** it by 5 days |
| `components/map/RuntimeSpanMap.tsx` | **2026-09-06** | **built the day AFTER** |

**Two failures, not one.**

**(a) A retrofit that never happened — three surfaces.** `IntakeRoute`, `LocationMap` and
`FileReport` were written when there was no flag to read. Nothing is wrong with how they
were built; the contract arrived later and nobody swept the existing consumers. This is
ordinary follow-through debt, and it is invisible because adding a field to a response
breaks nothing.

**(b) A convention that did not propagate — one surface, and it is the important one.**
`RuntimeSpanMap.tsx` was added **2026-09-06**, one day after the contract landed. Its data
path is explicit about what it discards (`:155-161`):

```ts
.runSpec(SPEC_ID, {})
    ? { state: 'ready', rows: checked.rows }
```

It takes `rows` off the envelope and drops the rest. A developer building a new spec
consumer the day after `truncated` shipped had no way to learn it existed: it is not in a
convention document, no lint rule mentions it, no shared hook surfaces it, and the three
components that DO honour it are not the ones a new map would be copied from.

**Consequence, stated at the product level because that is where it lands.** The prior
report ranked this #1 for a reason that has not changed: *"the export labelled 'full'
inherits it"*. A map that plots 500 of 3,000 hosts is not a map with a missing badge — it
is **a wrong picture of the estate**, and a picture is exactly the artefact a reader trusts
without checking a row count. `RuntimeSpanMap` and `LocationMap` are both spatial: their
failure mode is a sparse map that looks complete.

**This is slot 10's conclusion, confirmed with dates rather than argued.** The first cycle
said *the right answer exists six times and does not propagate*. Here is the propagation
event itself, measured: contract on 09-05, new consumer on 09-06, flag dropped.

**Cheapest correction, and the two halves are genuinely different work:**
- For **(a)**, a sweep: three surfaces, each reading a field it already receives. Small,
  mechanical, and worth doing in one change so the count reaches 8 of 8.
- For **(b)**, the fix is NOT a fourth implementation. It is to make the envelope hard to
  drop — a shared hook or helper that returns rows and completeness together, so
  `checked.rows` stops being the natural thing to write. That is the "instrument that makes
  the wrong version fail" slot 10 asked for, and this slot is the first place it can be
  built rather than described.

### L2-2 — the coverage ratchet was set to the tree of four days and 12,482 lines ago

`web/package.json:17` runs in CI (`.github/workflows/ci.yml:304`):

```
vitest run --coverage --coverage.thresholds.statements=9.8
                      --coverage.thresholds.branches=70
                      --coverage.thresholds.functions=50
```

**WEB13 built this correctly and reasoned about the exact failure I went looking for.** Its
title says *"a floor at today's 7.51 percent"*, and its notes record the correction: setting
the ratchet to a stale number *"would install a floor already 2.4 points below the tree,
which is a ratchet that ratchets"* nothing — so the floor was moved to 9.8 to match the tree
on **2026-09-05**.

**The risk is that the same reasoning now applies to the ratchet itself.** The floor was
pinned to a 22,715-line tree. The tree is 35,197 lines. If the 12,482 new lines are less
covered than the old ones — which is the ordinary case for new UI surfaces, and this report
found four of them dropping a response field — then the floor is once again below the tree,
and a ratchet below the tree is precisely what WEB13's notes call a ratchet that does not
ratchet.

**I could not measure this and will not assert it.** `web/node_modules` is absent in this
worktree, so `npm run test:coverage` did not run here. What this report establishes is the
*condition* for the check, not its result:

> Run `npm run test:coverage` in a worktree with the install (`ui-workstream`). If the
> reported statement coverage is materially above 9.8, the floor is stale by WEB13's own
> standard and should be re-pinned. If it is at or below, the ratchet is doing its job and
> this entry closes.

That is a five-minute check with a decision attached, and it is worth an item precisely
because nobody will notice the answer either way: a floor below the tree passes silently,
which is the failure mode this whole sweep has been finding in other clothes.

**Note the shape.** `branches=70` and `functions=50` sit far above `statements=9.8`, which
is an unusual profile (statements normally exceed branches). This report does not explain
it and does not guess — the denominators may differ by `include`/`exclude` config. Whoever
runs the check above should look at the three numbers together, because if the statement
figure is measured over a much wider file set than the other two, "9.8" and "70" are not
comparable quantities and the ratchet's shape deserves a second look rather than a bump.

## Ranked

cycle ended on.

1. **L1-1(b) — a consumer built the day after the contract dropped it.**
   `RuntimeSpanMap.tsx`, added 2026-09-06, takes `checked.rows` and discards the envelope
   `truncated` rides on; the contract landed 2026-09-05. Ranked first because it is not one
   more instance of the sweep's pattern — **it is the propagation event itself, caught with
   dates**, and it shows the failure is not ignorance but absence of a mechanism: nothing

   describe — a shared hook returning rows and completeness together, so `checked.rows`
   stops being the natural thing to write.
2. **L1-1(a) — three older surfaces were never retrofitted.** `IntakeRoute` (08-10),
   `LocationMap` (08-22), `FileReport` (08-31) all predate the contract. Ranked second
   because nothing was built wrong and the correction is mechanical: three surfaces reading
   a field they already receive, which takes the count from 4/8 to 8/8. Worth doing in one
   change.
3. **L2-2 — the coverage ratchet may be below the tree again, and nobody would notice.**
   Floor pinned at 9.8 on 2026-09-05 against a 22,715-line tree; the tree is now 35,197.
   Ranked third and explicitly **unverified in this venue** — the report supplies the check
   and the decision rule rather than a claim.

**Not ranked, and the reason the second pass was worth running:** the prior report's
zero-deferral-markers claim **held through +12,482 lines**, and the producer half of its
ranked #1 is genuinely fixed. A second pass that only found new problems would be missing
half its job.
