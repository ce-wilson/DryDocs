## What holds

**This is a well-built package, and the findings below are not about its craft.** Slot 7's
hygiene signals were right as far as they went: zero hatches over 1,105 lines, `ruff` clean,
92% covered, and every non-obvious decision carries the reason it was made. What follows is
what a design read adds to that, and it is a different kind of problem.

1. **One number, one home, two doors.** `config/doc-capture.yaml` holds the page ceiling, the
   politeness delay and the scheme allow-list, and both the standalone scraper and the
   component's web connector read it (`policy.py:21`). "Too many pages" cannot mean two
   things depending on which entry point the operator used. `test_docmeta_pipeline.py:218`
   asserts neither number is a literal in either consumer — the guard for ADR 0014's no-literals
   rule, applied to a value that governs how a third party is treated.
2. **The refusal is a pre-flight, and it is exact.** `enforce_ceiling` runs against a fully
   resolved location list before the first request (`web.py:65`, `filedrop.py:44`), which works
   only because a connector never discovers its own size — every capturable set comes from the
   publisher's own manifest. That is why this can refuse rather than abort halfway, and the
   docstring says so at `base.py:9-12`.
3. **A refusal and a failure are different types.** `TooManyPagesError` / `DisallowedSchemeError`
   mean *we declined and fetched nothing*; `SourceUnavailableError` means *we tried and the world
   said no*. `base.py:21-28` states that only the second should be retried, and
   `test_docmeta_connectors.py:160` pins it. This is the distinction the rest of the repo has
   been rediscovering all cycle, already made here.
4. **The digest is over raw bytes, never the cleaned text** (`manifest.py:11-13`). Hashing after
   cleaning would make a change to our own cleaner indistinguishable from a vendor edit, which
   are exactly the two things freshness exists to tell apart.
5. **The token count carries how it was produced** (`tokenizer.py`). `TokenCount.method` is
   `tiktoken` or `whitespace-words-x1.3`, and a caller that cares can refuse the estimate rather
   than discover the difference in a truncated prompt. Measured in this venue: `tiktoken` is not
   installed, so the labeled fallback is the live path — the label is not decorative here.
6. **Determinism is defended where it is load-bearing.** `sort_keys` plus an explicit `newline="\n"`
   on the manifest write (`manifest.py:203-213`, J49), sorted directory reads in filedrop, a
   stdlib-only cleaner with no "smart" extraction. Every one of those exists so a re-run over
   unchanged content produces an identical file, which is what makes a digest comparison mean
   anything.
7. **The curation ladder is derived, not declared** (`registry.py:31-39`). An entry cannot soften
   its own gate, because `required_curation` reads `CURATION_BY_TIER[tier]` and ignores what the
   row claims. `test_docmeta_pipeline.py:253` is named for exactly that.
8. **A capture run that cannot name its ledger row does not run** (`registry.py:150-196`, Q23).
   Not a warning — an error, with the ambiguous case naming every candidate it matched. This is
   the strongest single piece of design in the package.

## Lens 1 — system design

### S1 — `capture-manifest.json` has two incompatible writers, and this package is on neither end of the live path

The component owns the filename: `MANIFEST_FILENAME = "capture-manifest.json"` and
`SCHEMA = "drydocs.docmeta-manifest.v1"` (`manifest.py:51-52`). But the only capture that runs
today is `scripts/external_vendor_scrape.py`, which builds its own dict and writes the same
filename directly (`:371-395`), and the only consumer is
`drydocs/loaders/vendor_docs.py:169-208`, which reads that dict's keys. Neither imports
`CaptureManifest`.

Measured, both directions:

```
direction 1 — component reads the live file:  TypeError: PageRecord.__init__()
                                              got an unexpected keyword argument 'url'
direction 2 — live consumer reads a component manifest:
    node['page'] MISSING   node['title'] MISSING   node['anchor'] MISSING
    node['breadcrumb'] MISSING   node['toc_path'] MISSING   node['source_url'] MISSING
    node['sha256'] present
```

One key in common out of seven. The top-level key sets overlap on five of nineteen
(`captured_at`, `classification`, `corpus_id`, `pages`, `trust`).

**Consequence.** ADR 0006's Decision 4 says freshness is gate-preserving: *"a sha256 change on
refetch RE-QUEUES curation — a changed page never silently overwrites confirmed content"*, and
the plan's invariant 4 repeats it. The code that implements that rule is `CaptureManifest.diff`
and `DigestDiff.needs_regate` (`manifest.py:232-258`) — correct, tested, and unreachable from
any real capture, because the artifact it reads is written in a schema it cannot parse. The
ADR's central promise about vendor drift currently has no live instance. This is not a bug in
either file; it is a seam nobody owns, and it is invisible from inside either one.

**Cheapest correction.** Not "rewrite the scraper". Decide which shape is the schema of record
and write that decision down: either the scraper builds its manifest through `CaptureManifest`
(its per-page extras become `meta`, which `RawPage` already has a slot for), or the component's
manifest is declared internal and gets a different filename so two schemas stop sharing one name.
Either way the P5 freshness work has a defined input; today it has two.

### S2 — `theme_coverage()` drops a page it does not recognise, from all three populations at once

`ThemeCoverage` exists to stop one misleading number: classified, unclassified and out-of-scope
are reported apart because *"a single untagged number would make the difference unmeasurable"*
(`manifest.py:82-84`). But the tally initialises a dict from the enum, increments
`counts.get(...)` for whatever string a page carries, and then reads back only the three known
keys (`manifest.py:189-196`). A page whose `theme_status` is outside the enum is counted into a
key nobody reads.

Measured on a two-page manifest, one `classified` and one carrying an unrecognised status:

```
pages on manifest = 2
coverage = ThemeCoverage(classified=1, unclassified=0, out_of_scope=0)
coverage.total = 1   in_scope = 1   ratio = 1.0
```

**Consequence.** `total` disagrees with `len(pages)` and `ratio` reads 100% while half the
corpus is unaccounted for. The reachable route to an unknown status is `read()`, which does no
validation (S3) — so a hand-edited or future-version manifest produces a coverage report that
is confidently wrong in the direction of "fully classified". This is the sweep's recurring
defect shape, found inside the one function written specifically to prevent it.

**Cheapest correction.** Count the unknown bucket and render it, or reject the status at
construction. Either is a few lines; the choice is whether an unknown status is data or an
error.

### S3 — the manifest is the one artifact that outlives a run, and the only one that does not check its own version

`policy.load` refuses a file whose `schema` is not `drydocs.doc-capture.v1` (`policy.py:45`),
and `load_doc_sources` does the same for the ledger (`registry.py:123`). `CaptureManifest.read`
does neither. Measured: a manifest relabelled `drydocs.docmeta-manifest.v99` reads back clean,
and the object reports that version as its own. The asymmetry runs the other way too — adding a
key raises `TypeError: CaptureManifest.__init__() got an unexpected keyword argument`.

**Consequence.** Strict where it should be lenient, lenient where it should be strict: a v2
manifest read by v1 code is silently misinterpreted, while a v1 manifest carrying one new field
crashes. Both land on the freshness comparison, which is the decision that re-queues SME
curation.

**Cheapest correction.** One `if raw.get("schema") != SCHEMA: raise` in `read`, matching its two
siblings, and pop unknown keys with a recorded reason rather than passing them to the
constructor.

### S4 — the scheme allow-list is enforced on the declared URL only; a redirect is never re-checked

`check_scheme` runs over `source.locations` before the first request (`web.py:70-71`), which is
the right place for the declared list. But `urllib_transport` (`web.py:39-43`) uses the default
opener, which follows redirects, and the connector never sees the post-redirect URL. Verified in
this venue's stdlib: `HTTPRedirectHandler.http_error_302` permits a redirect target whose scheme
is `http`, `https`, `ftp` or empty — so `ftp://` is reachable through a redirect from an
allow-listed `https://` URL, and the allow-list is documented as forbidding exactly that
(`config/doc-capture.yaml`: *"no business reaching file://, ftp://, gopher:// or a data: URI"*).
Host is unconstrained in either case: the allow-list is about schemes, and nothing bounds where
a redirect may point.

**Consequence.** Narrow but real, and it is the one guardrail in this package whose failure is
not self-announcing: the run succeeds and the manifest records the originally requested URL, not
where the bytes came from. `RawPage.meta` is documented as the place for HTTP status
(`base.py:43`) and the web connector never populates it, so nothing downstream can tell a
redirected fetch from a direct one.

**Cheapest correction.** Record the final URL and status in `RawPage.meta` and re-run
`check_scheme` on it, refusing after the fact — the bytes are already in hand, so the refusal
costs a request nobody can un-send, but the manifest stops recording a URL that is not where the
content came from.

### S5 — the ceiling counts pages; nothing counts bytes

`max_pages: 600` bounds how many documents a run may fetch. No policy field bounds the size of
one, and `_fetch_one` reads the whole response into memory (`web.py:102`) before anything sees
it. `config/doc-capture.yaml` names one of the ceiling's three purposes as avoiding *"committing
tens of MB of vendor copyright"*, which is a claim about bytes enforced with a count of pages —
the measured trees average roughly 19 KB per page, so 600 pages is about 12 MB at the average and
unbounded at the tail.

**Consequence.** A run that stays under the page ceiling can still be arbitrarily large. Lower
severity than S1-S3 because the corpora are vendor HTML and the observed sizes are small, but
the guardrail's stated purpose and its mechanism do not match, and that gap is what a reader of
the config would not expect.

**Cheapest correction.** A `max_bytes_per_page` in the same policy file, checked against
`Content-Length` where present and against the body otherwise.

## Lens 2 — technical debt

**The conventional axes are perfect and they are measuring the wrong thing.** Zero
`type: ignore`, zero `noqa`, zero `cast(`, zero `: Any`, zero `pragma: no cover`, zero
`TODO`/`FIXME` over 1,105 lines; `ruff check` and `ruff format --check` clean; 92.38% coverage
over the module's full test set. No hatch count can see this module's actual debt, which is that
almost none of it is called.

### T1 — six of the package's eight public entry points have no non-test caller

Measured across the tree, excluding tests, the package itself, and review prose:

| symbol | non-test call sites |
|---|---|
| `WebConnector` | **0** |
| `FiledropConnector` | **0** |
| `CaptureManifest` | **0** |
| `clean_html` | **0** |
| `estimate_tokens` | **0** |
| `load_doc_sources` | **0** |
| `CapturePolicy` | 2 — both `scripts/external_vendor_scrape.py` |
| `resolve_capture_registry_id` | 2 — both `scripts/external_vendor_scrape.py` |

The CLI confirms it from the other side: 55 registered commands (read from
`drydocs.cli.app.registered_commands`, J37), and **no `drydocs/cli*` module mentions
`drydocs_docmeta` at all**. The doc verbs that do exist — `convert-vendor-docs`,
`load-vendor-docs`, `load-bmc-docs` — run through `drydocs/loaders/vendor_docs.py` and
`drydocs_core/docs/vendor_html.py`.

**This is the same fact as S1, costed.** The acquisition half of the component is complete,
tested and parallel to the path that actually runs. It is not dead code — P4 and P5 are declared,
unbuilt phases in `knowledge/upgrade-plans/docmeta-component.md`, and a plan phase is a decision,
not an oversight (the sweep's own rule about separating chosen debt from unnoticed debt). What is
unnoticed is the divergence: the live path grew its own manifest, its own hashing and its own
HTML conversion while the component sat beside it, and nothing in either place records that they
are now two implementations of one idea.

### T2 — a guard's own comment asserts CLI verbs that do not exist

`tests/unit/test_runbook_coverage.py:69` explains why `drydocs-docmeta` moved out of the
placeholder list: *"has since been BUILT (Q6, ADR 0006: connectors, cleaner, manifest, policy,
registry, tokenizer + live CLI verbs)"*. The six modules are real. The live CLI verbs are not —
see T1. The guard still behaves correctly (docmeta belongs in `RUNBOOK_PENDING` either way), so
nothing is red; what is wrong is the reasoning a future reader inherits, and the same comment is
the repo's most authoritative-looking statement that this component is wired up. Two lines away,
the `drydocs-deepdoc` entry gets this exactly right — *"no CLI verb and no importer anywhere in
`drydocs/` or `drydocs_core/`, so there is no operable surface yet"* — which is the wording
docmeta's entry needs.

**Cheapest correction.** Restate the comment to what is true: built, offline-tested, no
entrypoint yet, and P4/P5 are where the verbs land.

### T3 — `scrub()` matches substrings, and redacts words that merely contain a hint

`_SECRET_HINTS` is matched with `h in k.lower()` over the key (`manifest.py:264-279`). Measured:

```
{'keywords': '<redacted>', 'authority': '<redacted>',
 'monkeypatched': '<redacted>', 'api_token': '<redacted>'}
```

`keywords` and `monkeypatched` contain "key"; `authority` contains "auth". The invocation record
exists so a run is reproducible and auditable, and `keywords` is precisely the field that says
what was asked for — redacting it destroys the audit content while leaving the audit file.
Matching the KEY rather than the value is right and the docstring's reason for it is right; the
substring test is what is wrong.

**Cheapest correction.** Split the key on `_`, `-` and case boundaries and compare segments, so
`api_token` still redacts and `keywords` does not.

### T4 — the filedrop docstring describes a shallower walk than the code performs

`filedrop.py:5-7` says a directory *"is read one level of `rglob` deep"*. `rglob` is fully
recursive, and measured on a fixture with a file three levels down, both files were fetched. The
file that decides what a corpus consists of is the wrong one to be approximate about: an operator
pointing at a share expects the documented depth, and the ceiling refusal at 600 is what would
catch the surprise.

**Cheapest correction.** Delete the clause — the behaviour is fine, the sentence is not.

### T5 — the 90 coverage floor reads as failed on this module under a natural scoping

`pyproject.toml:346` sets `fail_under = 90`. Measured here: `--cov=drydocs_docmeta` with only
the two obviously-named test files reports **89.05%** and prints
*"Required test coverage of 90.0% not reached"*; adding the two files that actually exercise the
registry (`test_doc_registry.py`, `test_capture_registry_join.py`) gives **92.38%**. Recorded so
the next reader who scopes a coverage run by filename does not go looking for a regression that
is not there — the module is above the floor; a two-file selection is not this module's test set.

### Chosen debt, reported as the cost of a decision and not as a defect

- **Two HTML converters.** `cleaner.clean_html` produces flat text for hashing;
  `drydocs_core/docs/vendor_html.html_to_markdown` (263 lines) preserves structure for chunking.
  `cleaner.py:9-13` names the other one, says which to reach for and why. That is a decision with
  its reason attached, and it stays one.
- **The estimate-shaped token count.** The fallback is ±15% on prose and worse on the tables and
  identifiers vendor documentation is full of (`tokenizer.py:4-9`), and it is the live path here.
  The label is the mitigation and it is correctly implemented; no caller reads `is_exact` today
  because there are no callers.
- **ADR 0021 is not adopted here, and that is currently correct.** No function in this package
  returns `CheckOutcome`, and none appears in `PROBES`. The type is for a result whose answer
  depends on something it had to go and look at; this package's public surface is pure over
  inputs it is handed. The one function that will qualify is the P5 freshness check — a refetch
  that compares against a previous manifest that may not exist. `DigestDiff.__bool__` is the
  shape to watch: measured, a diff of two empty manifests is falsey and re-gates nothing, which
  is the right answer for "nothing changed" and the wrong one for "nothing was fetched". P5 is
  where that distinction has to be made, not here.

## Ranked

**The headline is not a bug. It is a seam between two files that are each correct.**

1. **S1 — `capture-manifest.json` has two incompatible writers, and the component is on neither
   end of the live path.** Ranked first because it is the module's reason for existing: ADR 0006
   Decision 4 and plan invariant 4 both turn on a sha256 comparison between runs, the code that
   performs it is written and tested, and no real capture can reach it. Measured in both
   directions, one shared key of seven. Nothing is red, nothing is failing, and the promise is
   not kept.
2. **S2 — `theme_coverage()` drops a page it does not recognise, from all three populations at
   once.** Ranked second because it produces a *number a human acts on* that is wrong in the
   reassuring direction: measured, two pages in and `ratio = 1.0` with one of them unaccounted
   for. The function exists specifically to stop one misleading number.
3. **S3 — the manifest does not check its own schema on read, and crashes on an unknown key.**
   Ranked here rather than lower because it is the reachable route into S2 and because its two
   sibling loaders in this same package both do it correctly — the fix is one line and a
   convention already in the file next door.
4. **T1 with T2 — six of eight public entry points have no non-test caller, and a guard's comment
   says otherwise.** One finding from two sides. The orphaning itself is a declared plan phase
   (P4, P5) and therefore a decision, not a defect; what is unnoticed is that the live path grew
   its own manifest, hashing and HTML conversion beside a component that already had all three,
   and the most authoritative-looking sentence in the repo about this module's wiring
   (`test_runbook_coverage.py:69`) is wrong.
5. **S4 — the scheme allow-list is enforced on the declared URL only.** Verified against this
   venue's stdlib: a redirect may land on `ftp://` or any host, and the manifest still records
   the URL that was requested.
6. **S5 — the ceiling counts pages, and the harm it names is measured in bytes.**
7. **T3 — `scrub()` redacts `keywords` and `authority`.** Measured. The audit record survives;
   its content does not.
8. **T4 — the filedrop docstring documents a shallower walk than the code performs.** Measured at
   three levels deep.

**Not ranked, recorded so no later firing re-audits them:** the perfect hatch scores, the 92.38%
coverage, the two-converter split (a decision with its reason attached), the estimate-shaped
token count (labeled, which is the mitigation), and ADR 0021 non-adoption (currently correct —
this package's public surface is pure over inputs it is handed).

## Cross-links

**Between the lenses in this firing.** S1 and T1 are one fact approached from opposite ends.
Lens 1 asked what the component promises its callers and found the promise unreachable; Lens 2
asked what it costs to keep going and found there are no callers. Neither lens alone reads as
serious: a design read alone would call S1 a seam awaiting P5, and a debt read alone would call
T1 a plan phase. Together they say the seam has been quietly filled by something else.

**To slot 7, whose declining to read this package is what produced this report.** Its prediction
holds exactly: *"zero hatches, clean lint and green tests, which is evidence of hygiene and not
of design."* Confirmed — every hatch is still zero, and the two most consequential findings here
are structural and invisible to every count slot 7 took.

**To the sweep's unbroken pattern, slots 2 through 9 — "a result that cannot distinguish checked
and clean from not checked".** S2 is another instance, and the sharpest in one respect: it is
inside the function written specifically to prevent a single misleading number, and it produces
`ratio = 1.0`. It is also the first instance to arrive *after* the remedy exists. Slot 7's third
grooming candidate was "write the convention down and name the instrument"; that became ADR 0021,
ACCEPTED 2026-09-09, with `CheckOutcome` and a `PROBES` registry. S2 is not itself a probe defect
— the correction is to count the bucket — but the module's one future probe is named in Lens 2,
and P5 is where the type applies.

**To slot 10 (seams), forward.** S1 is a seam finding in slot 10's exact sense: two modules
disagreeing about a shared contract, where neither module is wrong from the inside and no
per-module lens can see it. The shared contract here is a FILENAME, not an import, which is worse
— the module boundary test cannot see it either, because nothing crosses a package boundary. A
seams firing should ask what else in this repo is coordinated by an agreed path rather than an
agreed type.

**To ADR 0006 and `knowledge/upgrade-plans/docmeta-component.md`.** Both remain accurate about
what should be true. Neither records that the vendor-docs path shipped its own capture format in
the meantime, which is the gap S1 names.
