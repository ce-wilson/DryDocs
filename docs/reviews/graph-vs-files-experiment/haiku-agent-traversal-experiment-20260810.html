All four workers under-reported their own tool use by 34–65%

27 v 41 · 10 v 26 · 28 v 47 · 11 v 31. Systematic across both tracks and both task types — haiku counts "logical steps" and drops retries, failures and report writes. Two self-reports are internally inconsistent on their face (o53-BETA claims 11 while enumerating 19). Both planning runs fabricated their timestamps — one claims a 90-minute span for a 306-second run, neither is near the 03:05 dispatch window.

Consequence for any re-run: self-reported metrics are unusable for cross-track comparison. Only orchestrator-observed numbers count, and the run log must capture them.

What neither track got right

Both coding runs missed the coverage-pin clause — so neither diff was adoptable

The acceptance's "coverage pin moved with the history-line convention" is the tuple (29, 68) in test_ui_components.py, whose docstring is the convention. Neither run touched it, so both worktrees leave the Python guard suite red — while both correctly report npm build and lint green. The web build cannot see this; only the repo's own drift guard can, and neither run ran it.

BETA additionally missed the (15) → (14) section header, breaking a second guard. Fable also found the coding prompt's pointer to "neighbouring retired rows" was itself a red herring — that yaml has no retired rows — and scored it evenly as a shared handicap.

Verdict

Planning: the graph helped, on the dimension that matters. It surfaced the existing port_preflight.py machinery that re-homes Idea-96 — the single most consequential correct fact in either plan — which ALPHA's eleven Globs never found. Unblinding made ALPHA's failure worse: it had unrestricted Grep over backlog.yaml, and one grep "- id: J18" would have caught the collisions. That was diligence, not tooling.

Coding: a wash on the diff, a hurt on the discipline. Both tracks converged on the same three files. BETA's 35% speed edge is worth nothing on a deletion task where the verification is the deliverable.

Fable's one improvement before a re-run is worth it

Extend the graph to the acceptance-bearing non-code surfaces — taxonomy ledger rows and guard-test pins as nodes joined to the code modules they inventory. Every BETA miss (PowerShell-locating ui-components.yaml, the unnoticed header count, the unnoticed pin) happened precisely where the graph goes blind, and O53-shaped chores live mostly in that blind zone. As fable put it: the worker didn't break the rules so much as walk off the edge of the map the rules assumed was complete.

Outcome

  • ALPHA (files) code set adopted by SME ruling — on discipline, not diff quality.
  • Applied on the post-O47 tree as a re-application, not a merge: the diffs were cut before O47 moved the same surfaces, so the yaml hunk re-applied against (16) and the pin moved 70 → 69 — the clause both runs missed, fixed at adoption.
  • Orphan re-verified by grep before and after the delete. Build green, lint at the three pre-existing warnings, full suite 1836 passed / 5 skipped.
  • O53 closed as c9ea9fc; the full experiment record committed as c353956.

That adoption step is the standing lesson: an experiment diff is a candidate, not a merge. Both candidates were red on the repo's own guards; the review caught what the runs did not.
